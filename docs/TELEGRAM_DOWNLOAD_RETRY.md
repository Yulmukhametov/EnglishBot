# Повтор скачивания входящих голосовых Hermes

Исправление для повторяющейся ошибки `Couldn't download your voice message (TimedOut)`.
В просмотренном Telegram-адаптере Hermes v0.23.1 `_cache_inbound_av` вызывал `get_file()`
и `download_as_bytearray()` по одному разу, без явных тайм-аутов.

## Поведение

- До трёх попыток получения файла и его скачивания, с ожиданием 1 и 2 секунды между ними.
- Повтор только при PTB NetworkError (включая TimedOut) или локальном истечении времени.
- BadRequest и Forbidden не повторяются; отмена задачи сохраняется.
- Тайм-аут соединения 10 с, ожидания пула 5 с, чтения метаданных 20 с и аудио 30 с.
- Одна попытка ограничена 40 с, всё скачивание вместе с повторами — 90 с.
- Это повтор безопасных GET-запросов: AI, запись учебного ответа и отправка сообщений
  не запускаются повторно. Успешный результат передаётся прежней обработке ровно один раз.
- В новых сообщениях журнала нет файловых URL или секретов.

Это не устранит постоянную недоступность Telegram, неправильную маршрутизацию или отказ
самого сервиса. После исчерпания попыток сохраняется штатное сообщение об ошибке Hermes.
Первый разовый сетевой сбой теперь может восстановиться без повторной отправки пользователем.

## Установка

Это локальная совместимая правка исходников установленного Hermes, не настройка OpenAI.
Устанавливать под владельцем существующего English Bot (`hermes`), не root и не пользователем
второго помощника. Установщик не меняет модели, токены, голоса, учебные данные и другие сервисы.

По одной команде:

```bash
git -C /home/hermes/EnglishBot-delivery pull --ff-only
```

```bash
bash /home/hermes/EnglishBot-delivery/deploy/install-telegram-download-retry.sh
```

После сообщения «Исправление установлено» либо «Исправление уже установлено»:

```bash
/home/hermes/.local/bin/hermes gateway restart
```

Путь ищется под текущим HERMES_HOME в `hermes-agent/plugins/platforms/telegram/adapter.py`
или прежнем `hermes-agent/gateway/platforms/telegram.py`. Если версия/путь не соответствуют
ожидаемому обработчику, установка остановится до записи. Не добавлять --force и не менять
вслепую чужие экземпляры Hermes. Для нестандартной установки после проверки можно передать
`--adapter /проверенный/путь/adapter.py`.

Перед заменой оригинал сохраняется рядом с суффиксом `.englishbot-download-retry.bak`.
Существующая резервная копия не перезаписывается. Повторная установка того же исправления
безопасна. Обновление самого Hermes может убрать правку — после него проверить код и заново
применить установщик, если версия совместима. При конфликте сохранить обе версии и разобраться.
Для отката восстановить именно этот backup в указанный установщиком adapter.py и перезапустить
gateway того же пользователя; сначала убедиться, что после патча Hermes не обновлялся.

## Проверка

После перезапуска отправить несколько обычных новых голосовых. Не делать вывод об исправлении
нестабильного соединения по одному успешному сообщению. При новых сбоях посмотреть журнал:

```bash
journalctl --user -u hermes-gateway.service -n 80 --no-pager
```

Новые строки `Inbound media download interrupted; retry 1/2` означают, что повтор работает.
Перед передачей журнала удалить ключи и личные данные из других строк.

Автотесты: `pytest -q tests/test_telegram_download_retry.py`. Покрыты временные ошибки в обоих
этапах, ограничение попыток и общего времени, отмена, постоянные ошибки, отсутствие URL в новом
логе, проверка версии, резервная копия и повторная установка. Дополнительно установщик проверен
на загруженном оригинале адаптера v0.23.1. Реальное соединение VPS с Telegram в этой среде
недоступно; результат на сервере требует установки и наблюдения пользователя.
