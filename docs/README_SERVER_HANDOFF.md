Составлено 12 ноября 2026 года по переписке, исходникам и результатам проверок пользователя.
Это описание существующей установки, а не отчёт о новом SSH-аудите сервера.
Паролей, токенов, API-ключей и OAuth-секретов в файле нет.
Публичная копия для передачи контекста в новый чат. Адрес сервера и системное имя скрыты;
владелец при необходимости возьмёт их из панели провайдера. Секретов в документе нет.

## Задача нового чата

Пользователь хочет разместить **ещё одного помощника на этом же VPS**, сохранив работающего
Telegram-репетитора английского. Назначение второго помощника ещё не определено в этом файле.
Сначала уточнить его задачи и интерфейс, осмотреть ресурсы и выбрать изоляцию.
Не считать этот документ командой немедленно переустанавливать Hermes или менять English Bot.

Пользователь не системный администратор. Ему нужны короткие инструкции на русском, команды
по одной и точное указание, где их выполнять: локальный терминал, SSH или Telegram.
Секреты он вводит сам на сервере. При скрытом вводе пояснять, что отсутствие символов нормально.
Сложные команды с `&&`, кавычками и `|` иногда искажались при копировании.
Если есть доступ к рабочему окружению, самостоятельно готовить и проверять файлы;
не утверждать, что изменение применено на VPS, пока это не подтверждено.

## 2. Что реально запущено

Работает **Hermes Agent от NousResearch**, подключённый к Telegram.
Устанавливался релиз v0.23.1; фактическую версию сейчас проверить перед изменениями.

Это не изначальное отдельное Python-приложение EnglishBot из корня репозитория.
В репозитории есть два разных подхода:

1. `englishbot/`, основной README и `docs/SERVER.md` описывают раннюю версию на OpenAI API.
   Их наличие не доказывает, что запущен сервис `englishbot` из `/opt/englishbot`.
2. **Используемый вариант:** Hermes + два установленных skill + отдельные программы доставки
   и хранения учебного прогресса. Ориентироваться на `hermes-skills/` и документы `HERMES_*`.

Основная модель преподавателя была выбрана **gpt-6.1-sol**, провайдер Codex, авторизация
пользовательским аккаунтом ChatGPT с Plus. Своя нейросеть на VPS не запускается.
Изначально reasoning был `medium`. Позже рекомендована команда Telegram `/reasoning low`
для ускорения; пользователь не подтвердил её применение. Текущее значение проверить.

### Автозапуск

Hermes работает как **пользовательский systemd-сервис**, от пользователя `hermes`:

```text
hermes-gateway.service
```

Ранее подтверждены `active (running)`, включённый автозапуск и linger, сохраняющий сервис
после закрытия SSH. Файл unit был установлен в:

```text
/home/hermes/.config/systemd/user/hermes-gateway.service
```

Для работы user systemd настраивались `dbus-user-session`, `loginctl enable-linger hermes`
и запуск `user@UID.service`. При ошибке `Failed to connect to bus` не переустанавливать бота;
проверить пользовательскую D-Bus-сессию и linger. В проблемной сессии помогало:

```bash
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
export DBUS_SESSION_BUS_ADDRESS="unix:path=$XDG_RUNTIME_DIR/bus"
```

## 3. Текущая цепочка обработки сообщений

```text
Telegram (polling)
    ↓ загрузка голосового на VPS
OpenAI API: gpt-4o-transcribe → текст
    ↓
Hermes / Codex / gpt-6.1-sol → преподаватель и подготовка ответа
    ↓ чтение/запись учебной SQLite через learner
english-lesson-delivery/send-lesson
    ↓ Edge TTS, обработка и сборка аудио через FFmpeg
Telegram Bot API → сообщения строго по очереди с подтверждениями message_id
```

Текстовый ввод минует распознавание речи.

### Распознавание — платный OpenAI API

Последняя рабочая настройка, которую пользователь проверил голосовыми:

```yaml
stt:
  provider: openai
  openai:
    model: gpt-4o-transcribe
    language: ""
  language: ""
  prompt: "Mixed English and Russian speech. Preserve both languages as spoken, including grammatical mistakes. Do not translate."
```

Ключ сохранён отдельно как **`VOICE_TOOLS_OPENAI_KEY`**, через `hermes config set`.
Не заменять ради распознавания авторизацию преподавателя Codex на платный OpenAI API.
Ключ голосовых инструментов технически может использоваться и другими OpenAI audio-инструментами,
если их включить; само наличие ключа не означает, что они сейчас используются.

Ранее пробовали локальный Whisper base/small, Groq whisper-large-v3-turbo/large-v3,
ElevenLabs Scribe v2. Русские вставки в английском систематически искажались.
Пользователь также проверял Scribe на сайте ElevenLabs — нужного качества не получил.
В конфигурации и `.env` могут остаться неиспользуемые настройки и ключи этих сервисов.
Не удалять секреты и не возвращать старый провайдер без причины.

С OpenAI пользователь подтвердил хорошее качество, в том числе сохранение `an evening`
и русской вставки «лёг спать». При невнятной речи модель всё же может сглаживать ошибки.
По одной расшифровке нельзя надёжно оценивать произношение или считать услышанное точным.

### Ответные голосовые — Edge TTS

Пользователь проверил `hermes config get tts.provider`: **edge**.
В установленном скрипте доставки подтверждены `import edge_tts` и `edge_tts.Communicate`.
Следовательно, предусмотренная доставка уроков использует Edge, а не OpenAI TTS.
На VPS нет локальной большой модели синтеза; Edge обращается к внешнему сервису.

В исходниках доставки русские фрагменты озвучивает `ru-RU-SvetlanaNeural`,
английские — `en-US-JennyNeural`. Голосовые настройки отдельно сохраняются в JSON,
фактические скорость/высоту/паузу читать из него, а не угадывать по умолчанию.
После нескольких настроек пользователь решил оставить голос как есть.

## 6. Особенности поведения English Bot

Пользователь изучает английский. Может намеренно говорить русское слово внутри английской
фразы, если не знает перевод. Бот переводит эту вставку, объясняет и сохраняет слово;
само переключение языка не является грамматической ошибкой.

При разборе стандартный порядок:

1. Голос: разбор ошибок на русском с английскими примерами.
2. Текст первого голоса: исходная фраза с зачёркнутыми ошибками, жирными исправлениями,
   полная правильная фраза, объяснение в цитате, при необходимости разговорный вариант.
3. Голос на английском: продолжение разговора или следующее задание.
4. Текст второго голоса под спойлером, чтобы сначала тренировать слух.

Четыре сообщения нужны не всегда. Для уточнения задания по-русски — один русский текст;
для английского продолжения без разбора — английское голосовое и текст под спойлером.
Разбор не должен включать инструкции следующего задания.

Скрипт готовит оба аудио перед началом отправки, затем отправляет по очереди с `message_id`.
Есть блокировка от перемешивания уроков и журнал доставки с идемпотентностью.
Не отправлять весь набор параллельно и не обходить защиту новым request_id после сбоя:
это раньше приводило к дублям и неправильному порядку.

После успешной отправки skill требует финальный ответ модели **ровно `NO_REPLY`**.
Иначе Hermes дополнительно отправляет обычный ответ и возникает дублирование.
Установщик разрешает тишину только в DM владельца через
`platforms.telegram.channel_overrides.<owner_id>.allow_silence=true`.
Числовой ID и Telegram-токен читать локально, не переносить в новый публичный документ.

### Учебная логика и ограничения

`learner state` читается перед учебным ходом. Есть профиль целей, времени, интересов и стиля;
шесть диагностических шагов, предварительный уровень, история ответов, темы ошибок,
русские словарные подсказки и каркас плана первой недели.
Команды хранилища: `state`, `next-task`, `set-profile`, `record`, `finalize`.

Полноценные контроль освоения каждой темы, повторная диагностика, SRS-расписание слов,
отслеживание домашних заданий и напоминания ещё не реализованы.
Произношение по звукам не оценивается: преподаватель обычно получает текст ASR.
Технические тесты распознавания не должны засчитываться как новые диагностические попытки.

Программа рассчитана на **одного владельца**. Доставка отказывается работать с несколькими
разрешёнными пользователями, учебное хранилище не является готовой многопользовательской системой.
Нельзя просто добавить друзей в allowlist и обещать независимые профили.

### Уведомления и скорость

Пользователь просил скрыть сообщения `💾 Self-improvement review: ... patched`.
Ему даны команды `hermes config set display.memory_notifications off` и перезапуск;
применение не подтверждено. Эта настройка скрывает уведомления, а не выключает сам review.
Фоновое самоизменение skills могло остаться включённым.

Ответы иногда медленные: модель, чтение/запись состояния, генерация нескольких фрагментов
Edge TTS, FFmpeg и ожидание подтверждений Telegram суммируются.

Бывала ошибка `Couldn't download your voice message (TimedOut)` при скачивании из Telegram,

повтора этого скачивания не было. Не увеличивать случайные тайм-ауты без диагностики.

## 7. Нагрузка и расходы

Основные AI-модели работают удалённо. После перехода с локального Whisper на OpenAI
локальная нагрузка распознавания должна снизиться. На VPS остаются Hermes, сессии,
доставка, FFmpeg, кэш и SQLite. Свежих замеров RAM/CPU из этого документа нет.

Для второго помощника запас **не гарантирован**. Оценить RSS процессов, available RAM,
swap, CPU и свободный диск до установки. Два независимых Hermes могут заметно увеличить
память; не обещать, что 2 ГБ хватит, и не требовать повышение тарифа без замеров.

Ориентиры, обсуждавшиеся с пользователем (не гарантированные будущие тарифы):

- VPS — 299 ₽/30 дней.
- Преподаватель — существующая ChatGPT Plus/Codex-авторизация и её лимиты.
- Входящие голосовые `gpt-4o-transcribe` — около $0,006/мин;
  10–15 мин ежедневно за 30 дней ≈ $1,80–2,70.
- Предусмотренная озвучка через Edge — без отдельной оплаты OpenAI TTS.

Второй помощник при общей авторизации будет расходовать общие лимиты; это не новый
независимый лимит Plus. Не выбирать его платные модели или API по одному факту наличия ключа.

## 8. Рекомендуемое разделение второго помощника

Это **план**, а не уже выполненная установка:

- Предпочтительно отдельный Linux-пользователь, например `assistant2`, собственный HOME,
  HERMES_HOME, конфигурация, секреты, сессии, skills, базы и каталог проекта.
- Отдельный systemd-сервис и отдельные логи. Имя `hermes-gateway.service` в другом user
  manager технически может повторяться; root должен различать владельцев процессов.
- Если нужен Telegram — отдельный бот и новый BotFather-токен, отдельный allowlist.
  Два polling-процесса с одним токеном конфликтуют и могут нарушить работу English Bot.
- Не копировать `.hermes` целиком и не разделять SQLite/журналы доставки между помощниками.
  Не давать новому помощнику права записи в каталог репетитора без необходимости.
- Авторизацию второго экземпляра настраивать отдельно штатным способом после выбора
  провайдера; не переносить OAuth-файлы вслепую. Проверить поддержку нужного сценария.
- Для Telegram polling отдельный домен и входящий порт обычно не нужны.
  Если у второго помощника будет веб-интерфейс/webhook, отдельно решить доступ извне:
  сервер за NAT, произвольный открытый порт не обязательно достижим публично.

Перед изменениями сделать защищённую копию конфигурации, установленных skills и учебной
базы. Живую SQLite сохранять штатным backup-механизмом SQLite, либо при остановленной записи;
простое копирование одного файла во время записи не гарантирует согласованную копию.
Резервная копия секретов должна оставаться на сервере/у пользователя, не в Git и не в чате.

## 9. Безопасные начальные проверки

От root или другого пользователя с правами чтения общих показателей, по одной команде:

```bash
free -h
```

```bash
df -h /
```

```bash
uptime
```

```bash
ps -eo user,pid,pcpu,pmem,rss,comm --sort=-rss
```

Под `hermes`:




Журнал текущего сервиса:

```bash
journalctl --user -u hermes-gateway.service -n 60 --no-pager
```

Перед отправкой журнала в чат проверить его на ключи, URL с токенами и личные тексты.
Для начальной диагностики не выводить `.env`, OAuth-файлы, весь config.yaml или дамп окружения.
